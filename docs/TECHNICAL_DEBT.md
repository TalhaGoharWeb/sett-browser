# TECHNICAL DEBT — SETT Browser

Audit date: 2026-10-31. Every item cites the file(s) that evidence it.
Ordered roughly by "will hurt soonest".

## D1. Release size and R8 (High)
- R8 minification/shrinking is **off** (`app/build.gradle.kts`:
  `isMinifyEnabled = false`, with the recorded rationale: GeckoView/AC
  are reflection-heavy; enable only after on-device testing).
- Result: arm64 APK **235,795,238 bytes (~236 MB)**, armv7 ~192 MB
  (TEST_RESULTS_040). Most of the mass is the GeckoView omni AAR and
  native libraries, which R8 cannot remove — but DEX/Kotlin shrinking and
  resource shrinking are untested wins left on the table, and the
  reflection risk is asserted, never measured. No size budget exists.
- The `release/` folder accumulates every historical APK (~3.3 GB on
  disk); local housekeeping only, but it slows any full-tree operation.

## D2. Test automation ceiling (High)
- Exactly **one JVM test class / 7 tests** (`SettLogicTest.kt`), covering
  the two pure-Kotlin rules. Everything else — engine wiring, settings
  application, undo flow, error pages, insets — is verified by code
  reading and manual on-device acceptance.
- **No instrumentation tests can run in the build environment** (no KVM/
  emulator; TEST_RESULTS_040 states this), and there is **no CI**
  (no `.github/` directory): unit tests run only when a human runs them.
- Release verification (badging/apksigner/zipalign/DEX greps) is a manual
  ritual recorded in TEST_RESULTS_040, not a script. One skipped step
  ships silently.

## D3. Single-activity programmatic UI (High, structural)
- All UI lives in one 734-line `BrowserActivity.kt`; tabs tray, bottom-
  sheet menu, settings, shields, downloads, and dialogs are constructed
  in code with hardcoded colors (`#0B1626`, `#2DD4BF`, … as string
  literals throughout) despite a palette existing in `res/values/colors.xml`.
- Exactly **one layout XML** and **no `strings.xml`**: every UI string is
  a hardcoded English literal in Kotlin or in the start-page HTML. No
  localisation is possible without a refactor — notable because the
  developer's other products ship bilingual (EN/UR) as a matter of course.
- No ViewModel/lifecycle-aware state holder of the app's own; the
  activity re-renders imperatively from the store flow with manual
  change-guards. Workable now; each new surface (bookmarks, history,
  dashboards, tools) multiplies the tangle. This is the gating debt for
  the master plan's Part 18 multi-section UI.

## D4. Build fragilities (Medium)
- **AAR-metadata check disabled** (`app/build.gradle.kts`): AC 159 AARs
  declare minCompileSdk 37; Sett compiles at 36 after the v0.1.0 preview-
  stamp install failure. The workaround is one Gradle bump away from
  breaking in either direction and must be re-justified per AC release.
- **AGP lint/UAST fragility**: during v0.4.0, lint crashed on a
  lambda-typed helper (Kotlin FIR UAST); fixed by redesigning the code
  (classify() refactor), i.e. the toolchain is shaping the code style.
- **Stale build property**: `android/gradle.properties` still carries
  `android.suppressUnsupportedCompileSdk=37,37.0` from the compileSdk-37
  era.
- **No Gradle wrapper** (`gradlew` absent): builds depend on a
  toolchain-local Gradle 9.3.1 path — reproducible in this VM, not for a
  fresh contributor.
- **Vendored dependency tree**: 274 MB of `local-maven` must be
  regenerated by a Python script before any clean build; it is
  environment-specific debt (proxy quirk) that a normal CI would not
  need, and it makes "clone and build" a documented procedure rather
  than a command (README build notes — which are themselves stale, D6).

## D5. Missing persistence layer (Medium)
- No database, no migrations framework, no export/import format. The
  master plan's Part 19 entities (bookmarks, history, downloads history,
  credentials, notes, study data) all require introducing storage +
  migrations + backup semantics from zero, into an app whose users
  already have session/settings data that must not be lost.
- Downloads list state lives only in `BrowserState`; Sett adds no
  download-history persistence of its own (A13 in the inventory).

## D6. Documentation drift (Medium)
- `docs/architecture.md` (Phase-2 design) describes at least eight
  components/features as if present that are not in the build
  (toolbar/awesomebar/readerview/contextmenu/prompts/webextensions
  components, bookmarks+history, measured-count dashboard, WebRTC and
  cookie-banner prefs, update manifest). It is the single most
  misleading file in the repo for a new reader.
- README licence paragraph attributes EasyList/EasyPrivacy usage to this
  product; Sett bundles no filter lists (the suite does). README build
  notes describe the abandoned compileSdk-37 setup.

## D7. Rename residue (Low)
- Post-rename leftovers from "Private X": `PrivateXApp` class name,
  root Gradle project name `PrivateX`, SharedPreferences file
  `privatex-settings`, `CrashLog` header text "Private X crash",
  `SettingsStore` doc comment "Private X's own settings".
  `applicationId` and the prefs filename must stay (update continuity);
  the rest is cosmetic debt that confuses contributors.
- `HomeUrls.LEGACY` is **not** debt to remove — it is a permanent
  compatibility obligation (session restore), documented in the file.

## D8. Small code smells (Low)
- `BrowserActivity` obtains the root layout twice via different routes
  (`findViewById(R.id.root)` for insets; `findViewById(R.id.progress).parent`
  for the find bar) — fragile if the layout changes.
- The start page is a ~9 KB HTML string with an embedded base64 PNG
  inside `Components.kt` — unreviewable as code, uneditable as design;
  any start-page change means editing a Kotlin string.
- Settings changes apply asymmetrically (ETP live to `engine.settings`,
  fingerprinting only at next engine creation, search immediately) — the
  toast text explains it, but the model will confuse future settings
  work.
- `HomeInterceptor.onLoadRequest` derives the search form's action URL by
  string surgery on `settings.searchUrl("")` (`substringBefore("?q=")`
  etc.) — works for the four current engines, brittle for a fifth.
- No `proguard-rules` file exists at all (consistent with R8 being off);
  enabling R8 later starts from zero rules for a reflection-heavy stack.
- Emoji are used as the icon set for buttons/menus (➕ 🕶 🔍 ⬇️ ⚙️ 🔥 ℹ️)
  and the shields button is the stock `ic_dialog_info` — placeholder-grade
  iconography, inconsistent with the custom mascot/adaptive-icon work.

## D9. Process debt (Medium)
- Solo-maintainer bus factor, acknowledged in `docs/roadmap.md` but with
  no handover note actually in the repo yet (the roadmap promises one
  "from Phase 3").
- Release pipeline is a manual sequence across three helper scripts
  (`vendor_mozilla.py`, Gradle, `upload_asset.py`) plus manual email;
  no release checklist file exists in the repo (the v0.4.0 record lives
  in docs/TEST_RESULTS_040.md after the fact).
- The GitHub-side state (repo settings, whether the API push respected
  `.gitignore` exclusions, SECURITY.md presence) was not verifiable from
  this audit's local evidence — see SECURITY_AUDIT_INITIAL S7/S11.
